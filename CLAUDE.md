## Вехи

Вехи M0…M5 (раздел 14) закрываются только своими тестами из раздела 12; без них следующая не начинается.
Состояние и открытые вопросы вех — `docs/M0.md`, `docs/M1.md`. Не тащи в код работу следующих вех без запроса.
Сценарии раздела 12 — `src/validation/` (метрики по снимку частиц, решатель за интерфейсом `Engine`): гейт
гоняется на CPU-эталоне (`npm run test:gate`), на GPU (e2e) и на устройстве (вкладка «Валидация»).

## Инварианты

- **Единицы ядра** (4.6): мм, мкс, мг → г/см³, км/с, ГПа, Дж. Никаких СИ внутри ядра.
- **У каждого числа есть источник** (принцип 0): параметр материала несёт `source` и статус
  `verified` / `check` / `tuned`. Не выдумывай значения и не повышай статус без сверки с первоисточником.
- **Детерминизм** — побитовый на одном устройстве (4.6): P2G копит массу и импульс в `atomic<i32>`
  с фиксированной точкой (`fixedPointScales` в `src/scene/scene.ts`). Никаких float-атомиков, случайности
  и зависимости от порядка потоков. Между устройствами побитового совпадения не требуется.
- **CPU-эталон** `src/cpu-ref/CpuMpm.ts` повторяет WGSL из `src/sim/kernels.ts` построчно. Меняешь физику
  в одном — меняй в другом; самопроверка (`src/sim/selftest.ts`, e2e) сравнивает их.
- **Режим совместимости WebGPU** (старые Android): workgroup ≤ 128 (используем 64), ≤ 4 storage-буфера
  на стадию, нет storage-буферов в вершинном шейдере, `@interpolate(flat)` только с `either`.
  e2e гоняет самопроверку и в `?compat`.
- **Раскладка частиц**: SoA-плоскости в одном буфере (`src/sim/layout.ts`, 20 плоскостей; TAG — материал,
  тело, поле контакта, флаг удаления; PHI — пористость откола); рендер берёт плоскости вершинными буферами
  по смещению.
- **Откол** (5.5) — пористость модифицированной Tepla: давление (1 − φ)·P_MG(J_s, e), рост пор неявным Эйлером
  по ln φ с фиксированной бисекцией (одинаково на CPU и GPU), разрушение при φ ≥ φ_f или φ·Δx ≥ δ_c.
- **Энергия** (12.2): кинетическая энергия, которую убирает сетка (разброс P2G, контакт полей, стенки, остаток
  G2P), уходит в тепло частиц через удельную потерю узла λ. Новое ограничение на сетке считает свою потерю
  по скоростям без толчка напряжений, иначе толчок у стенки посчитается потерей.
- **Границы области — по номеру узла** (узел `GRID_PAD` — на нижней границе, `g − 1 − GRID_PAD` — первый
  на верхней), не по координате: `origin + i·h` во float32 не попадает точно на стенку.
- **Фиксированная точка**: запас массы узла ×16 (`NODE_MASS_MARGIN`) — на скучивание частиц при больших
  сдвигах, не только на сжатие; в осесимметричном режиме GPU приводит массу узла к `nodeRefRadius` (в сетке
  всё — отношения накопителей узла). У K своя граница скорости (`kineticVelocityBound`) и округление со
  сдвигом из хеша (частица, узел, шаг): вклады хвостов шаблона меньше кванта иначе округлялись бы к нулю.
  Разности накопителей не срезай `max(…, 0)` — шум станет систематическим нагревом. Самопроверка сравнивает
  и энергию e; гейт на GPU — дрейф энергии.
- **Шаг = `gridUpdate` + `g2p2g`** (G2P этого шага + P2G следующего), первый P2G — ядро `p2g`.
  Режим хранения `l2` пишет v, C и VIZ только на последнем шаге пачки (`aux`) и берёт массу частицы
  из uniform — тем же выражением, что `prepareScene`. Режимы обязаны совпадать побитово (самопроверка).
- Ядро не знает об интерфейсе (13): на входе `PreparedScene`, на выходе буфер частиц.

## Команды

```bash
npm run typecheck && npm test   # быстро, без GPU
npm run test:gate               # гейт вехи на CPU-эталоне (раздел 12), ~2 мин
npm run test:e2e                # WGSL, гейт на GPU и рендер в Chromium на SwiftShader; собирает и поднимает preview
npm run android:sync            # сборка + копирование в android/
```

e2e запускает Chromium не в headless: в headless активный WebGPU-canvas роняет устройство
(«A valid external Instance reference no longer exists») и ничего не выводит. Без дисплея (CI,
облачная сессия) — `xvfb-run -a npm run test:e2e`. Замеры и проверки GPU открывают `?tab=device`:
вкладка «Демо» считает на том же GPU.
